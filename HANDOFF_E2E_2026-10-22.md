## Changes made in this development session

### Native session engine and stack

- New `apps/ccli/adapters/iec61850_mms/e2e/e2e_server.hpp/.cpp`: per-connection native handshake, negotiation, identity, DH, directional keys, replay state, protected transfer, renewal, signed release and security failures.
- New `e2e_wire.hpp`: bounded BER assembly/extraction and OID helpers. New `e2e_osi_bridge.h`: narrow C interface between the engine and stack overlay.
- New `scripts/generate_mms_e2e.py`: deterministic overlay after the existing certificate/TSP overlay. Hooks native AARQ, incoming transfer/control, all outgoing MMS including reports, tick and close. Adds native presentation syntax/context and extended session control lengths. Fixes abort parsing that previously retained stale payload. Legacy ACSE rejects an unhandled non-basic application context.
- `apps/ccli/cmake/mms_certificate_auth.cmake`: compatibility output in `generated/dual-certificate-base`, final native overlay in `generated/dual-certificate`; private presentation-header layout remains consistent. Generator avoids rewriting unchanged outputs.
- `package/ccli/Makefile` copies the new generator for SDK builds. CMake registers the engine.
- Native AC is `1.0.62351.4.2.1`, E2E abstract syntax `1.0.62351.4.1.2.1`; BER `2.1.1`; distinct odd context IDs.
- `e2e_codec.cpp` now accepts the actual tagged MMS open type for `ApplData`, rather than requiring a synthetic SEQUENCE. Exact received TBS/TBP contents remain authenticated.
- `e2e_association.cpp` verifies the raw signature envelope before typed signed-data semantics. Control messages have equivalent signature-first processing in `e2e_server.cpp`.

### Crypto, identity and product integration

- Live HMAC-SHA256, AES-128-GMAC and AES-256-GMAC; negotiated parameters; unique outgoing nonce prefix/counter and incoming per-key nonce checks. Non-12-byte GMAC nonce is permitted (bounded), with a 16-byte test case.
- `e2e_crypto.hpp/.cpp`: explicit `KeyAgreementUse::retained_server_rekey` permits renewal using the server's retained DH private key. Default initial derivation still rejects accidental reuse. Tests cover groups 14/23/28.
- Rekey carrier uses old client keys; changedKey acknowledgement uses old server keys; subsequent direction keys change. Both client and server epoch ages are bounded separately (`last_rekey`, `server_epoch_started`), including pending acknowledgement. Server reqRekey exists on outgoing traffic near deadline; real timed qualification remains open.
- New `apps/ccli/cmake/patch_mbedtls_3_6_crl_scope.py`: pinned/idempotent Mbed TLS 3.6 patch exposing opt-in scope-aware CRL parse functions. Native scope code examines critical issuingDistributionPoint before path verification. Default/TLS parser behavior stays strict. The vendored `library/x509_crl.c` is patched; do not revert it independently of this integration.
- New `e2e_mbedtls_crl.hpp` and `e2e_identity.cpp` integration. Added matching/wrong-URI/CA-only/partial-reason/malformed critical-IDP fixtures. Positive matching scope and all negative cases passed.
- `core/config/ccli_config.hpp/.cpp`: disabled-by-default native settings; strict E2E booleans/unsigned numbers, blank/unknown keys fail validation. Product rejects malformed native config even if a typo would otherwise leave native disabled.
- `mms_adapter.cpp`: native enable requires TLS with chain validation and commissioned Profile A. Validated application certificate goes through existing role authorization and owner-signed identity/TLS-fingerprint bindings. Native-only rejects compatibility unless explicitly allowed. Separate TLS and application leaf certificates checked at configuration and peer association.
- Product session token deletion stays with existing connection cleanup: **do not add a second native release callback that deletes the same token**. The native raw harness may use its own token lifetime.
- Private/session material is cleared. No real private keys, live configuration or device trust were changed.
