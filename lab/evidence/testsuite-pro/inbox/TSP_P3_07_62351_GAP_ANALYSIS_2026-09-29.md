## Root cause (62351-aligned)

TSP “Unable to verify signature” after valid RSASSA-PKCS1-v1_5 most likely means **62351-4 certificate / binding validation failed** inside TSP’s MMS Security module (OpenSSL error 00000000 is generic).

Priority gaps vs normative profile:

1. **Annex G.6.2 / §10.5.3 — address binding**  
   Auth cert subject must bind to **responding-AP-title + responding-AE-qualifier** in AARE. We send neither titles nor OID-bound cert → TSP strict mode rejects.

2. **Annex G.5.2 — keyUsage**  
   Missing `digitalSignature` + `keyAgreement` on E2E/auth cert → **invalid-public-key-certificate** path (§14.3.4).

3. **TSP MMS Security trust store**  
   Confirm `C:\CCLI_tls\root_CA.pem` in **MMS Security** (not only Transport TLS). Directory-to-CA empty is OK if root is loaded.

4. **Optional — dual cert (G.2)**  
   Some test tools expect TLS cert ≠ MMS auth cert; lab uses same `server.pem` (usually tolerated for A-profile).

## Recommended fix order

1. **PKI** — Regenerate `server.pem` with Annex G extensions (keyUsage) + subject OID for IED AP/AE (requires AP-title/AE-qualifier values from CID/SCL or TSP workspace).
2. **ACSE** — Add **responding-AP-title** (0xa4) and **responding-AE-qualifier** (0xa5) to AARE in `acse.c` (mirror TSP calling values or IED-specific values from SCL).
3. **TSP** — Verify MMS Security CA = `root_CA.pem`; retry Connect.
4. **Evidence** — Capture `TSP_P3_07_LIVE_CONNECT_PASS` on success.
