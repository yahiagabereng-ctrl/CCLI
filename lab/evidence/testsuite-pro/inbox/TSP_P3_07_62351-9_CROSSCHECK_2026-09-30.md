## Executive verdict

| Question | Answer |
|----------|--------|
| Does **62351-9** define the failing MMS auth signature? | **No** — that is **62351-4 §11.2.2** (A-profile auth value over GeneralizedTime). |
| Can **62351-9** still explain TSP failure? | **Yes** — via **dual-cert PKI policy**, **certificate verification (§7.4)**, and **trust-store / keyUsage** rules that TSP may apply when validating the **embedded AARE certificate**. |
| Is P3-07 a **62351-9 PKI gate** failure? | **Partially** — **P3-09** (62351-9 enrolment/CRL) is **PASS** in lab; P3-07 residual is **62351-4 A-profile + cert profile (Annex G)** validated through a **62351-9 §7.4 verifier**. |
| Lab crypto on wire | **PASS** — RSASSA-PKCS1-v1_5 over `0x81` + GeneralizedTime verifies with **E2E** `server.pem` pubkey (`verify_62351_auth.py`). |

**Most likely root cause (62351-aligned):** TSP validates the §11.2.2 signature using the **Transport TLS peer certificate** instead of the **embedded E2E certificate** — violating **62351-4 Annex G.2** dual-cert model that **62351-9 §7.3 / K6.3** expects (Cert A TLS + Cert B E2E).

## Normative split (62351-9 vs 62351-4)

| Layer | Standard | P3-07 relevance |
|-------|----------|-----------------|
| MMS auth value (cert + time + signature) | **62351-4 §11.2.2** | TSP error text targets this layer |
| AP/AE binding in AARE | **62351-4 §10.5.3 + Annex G.6.2** | Subject OID / responding-AP-title / AE-qualifier |
| E2E cert extensions (keyUsage) | **62351-4 Annex G.5.2** | **digitalSignature + keyAgreement** |
| PKI lifecycle, CRL/OCSP, verification events | **62351-9 §5.7–5.9, §7.4, Annex D** | How TSP/DUT **validate** certs before trusting signatures |
| Transport TLS | **62351-3** | Separate cert (Cert A); must not substitute for E2E verify |

## 62351-9 clauses mapped to P3-07 failure modes

### 1. Dual certificate model — **PRIMARY MATCH**

| Source | Requirement | Lab state | TSP impact |
|--------|-------------|-----------|------------|
| **62351-9 Extract** K6.3 SOP | Enrol **TLS cert** (EKU serverAuth/clientAuth) **and** separate **E2E cert** (Annex G extensions) | **Implemented** — `server_tls.pem` + `server.pem` / `server_acse.key` | If TSP uses TLS peer cert pubkey for §11.2.2 → **verify FAIL** |
| **62351-4 Annex G.2** | Separate key pairs for transport vs application | Wire shows **779-octet E2E cert embedded in AARE** | Signature verifies with E2E cert only |
| **62351-9 §7.3.6–7.3.7** | EST/SCEP enrolment; distinct CSRs per role | Lab manual ceremony | Product: two EST cycles |

**Evidence:** `TSP_P3_07_SIGNATURE_ANALYSIS_2026-09-29.md` — `server.pem` → VERIFY PASS; `server_tls.pem` → VERIFY FAIL on same wire signature.

**62351-9 event if mis-verified:** Annex D **2.2** `CERT_V_PK_SIG_WRONG` (*public-key certificate signature could not be verified*) — note this event is **cert chain** wording; TSP UI collapses both failure types into “Unable to verify signature”.

---

### 2. keyUsage — **SECONDARY (profile mismatch risk)**

| Source | Rule | E2E cert (`server.pem`) | TLS cert (`server_tls.pem`) |
|--------|------|-------------------------|----------------------------|
| **62351-4 Annex G.5.2** | **digitalSignature + keyAgreement** required on E2E cert | Must satisfy for strict A-profile | N/A |
| **62351-9 §7.4.4.10 / Table D.2 2.19** | TLS client: **digitalSignature**; TLS server: digitalSignature and/or keyEncipherment | If TSP applies **TLS rules** to E2E cert → may reject missing **serverAuth/clientAuth EKU** | Has TLS EKU |
| **62351-9 Extract REQ-3519-NORM-006** | TLS certs: **serverAuth / clientAuth EKU mandatory** | E2E cert intentionally **different profile** | Compliant for TLS |

**Gap analysis note (2026-09-29):** early lab `server.pem` lacked G.5.2 keyUsage — **fixed in later deploy** (see signature analysis wire cert with `2.5.4.106` subject).

**62351-9 does not require keyAgreement on TLS certs** — applying §7.4.4 TLS table to an **Annex G E2E cert** is a **profile category error**, not a DUT signing bug.

---

### 3. Subject / identity binding — **62351-4 leads; 62351-9 §7.4.4.6 is weaker**

| Source | Rule | Lab wire (post-fix) |
|--------|------|---------------------|
| **62351-4 G.6.2** | Subject = **objectIdentifier** binding **responding-AP-title + responding-AE-qualifier** | AP-title `1.1.1.999.1`, AE-q **12** in AARE; subject UTF8String `1.1.1.999.1.12` |
| **62351-9 §7.4.4.6** | Validate CN, O, OU, C, **serialNumber** (802.1AR); RBAC exception in 62351-8 | E2E cert uses **OID-style subject** — may trigger `warning: subject not included…` in strict 62351-9 verifier **without** failing TLS path |

Strict TSP binding may require **OBJECT IDENTIFIER** encoding (not UTF8String) — **62351-4 G.6.2**, not 62351-9 Table 1.

---

### 4. Trust anchor / MMS Security store — **OPERATOR CHECK**

| Source | Rule | Action |
|--------|------|--------|
| **62351-9 §7.4.4.3 / §7.4.4.9** | Issuer trusted; path validation to anchor | Load `root_CA.pem` in TSP **MMS Security** trust (not only Transport TLS) |
| **62351-9 Annex D 2.10–2.11** | `CERT_V_PK_TA`, `CERT_V_PK_PATH` | Directory-to-CA **empty** OK if root loaded explicitly |
| **62351-9 §5.9 / Annex D Group 4** | CRL/OCSP | Lab CRL deny path **PASS** (P3-09) |

---

### 5. Clock sync — **NOT the failing point**

| Source | Rule | Lab |
|--------|------|-----|
| **62351-9 §7.7** | PTP/NTP for cert validity | NTP on DUT; GeneralizedTime on wire matches session |
| **62351-4** | ~10 min skew tolerance | No clock alarm on connect |

## Recommended actions (62351-9 informed)

1. **Confirm TSP verify key source** — embedded AARE cert vs TLS peer cert (G.2 / K6.3 dual cert). Quick test: single-cert mode (`tls_own_cert: server.pem`) per signature analysis §Recommended next steps.
2. **Keep dual cert for product** — align with **62351-9 §7.3** two-enrolment SOP; document in K6.3.
3. **TSP MMS Security** — trust anchor = lab `root_CA.pem`; CRL in both TLS and MMS sections.
4. **E2E cert profile** — issue per **62351-4 Annex G.5.2/G.6.2** under **62351-9 ceremony**; do not reuse TLS EKU/keyUsage template for Cert B.
5. **Evidence on pass** — log Annex D **1.5** enrol events + absence of **2.2/2.19/2.23** during TSP connect.
