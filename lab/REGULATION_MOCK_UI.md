# Regulation mock UI on TesPro TG544

**Product note (2026-10-05):** Operator **HMI is cloud-hosted** — see [CCI_Cloud_Operator_HMI.md](../knowledge-base/08-engineering/CCI_Cloud_Operator_HMI.md). This mock console is **lab-only** (P7-12: off in product image).

**URL:** `http://192.168.1.130/ccli/mock_console.html`  
**Deploy:** `lab/tg544-openwrt/deploy-regulation-ui.ps1`

## Features

| Panel | Purpose |
|-------|---------|
| **Mock inputs** | Plant, DSO (Wlim/WSd/w110), PF2 timing — builds `/etc/ccli/lab.yaml` |
| **Computed** | R01, R03, R05, L01/L02 preview (same equations as `core/dso/`) |
| **Live plant** | Polls `ccli --bench-status --json` every 2.5 s — **P**, **PF2**, **DIO1 ON/OFF**, permissive |
| **Standards table** | CEI / TR clause → reference value → **expected CCLI action** (DIO, stale, FC03) |
| **Apply** | POST yaml → TG544 → restart **ccli** procd |
| **Presets** | Figura 2 (~42 kW), Legacy 900 kW, O.11 custom |

## Backend (on device)

| Endpoint | Handler |
|----------|---------|
| `GET ?action=status` | `/var/run/ccli-status.json` (daemon writes every ~5 s) |
| `POST ?action=apply` | `ccli --bench-write-config /etc/ccli/lab.yaml` + restart |
| `GET ?action=regulation_live` | Full `--regulation-check --live --json` (brief stop/start for ttyS2) |
| `GET ?action=events` | `ccli --event-dump --count 40 --json` (O.14 log, read-only) |

CGI script: `lab/tg544-openwrt/cgi-bin/ccli-bench` → `/www/cgi-bin/ccli-bench`

## Zone dashboard (DSO · Operator · Plant)

**URL:** `http://<dut>/ccli/zone_dashboard.html` (`/ccli/` now lands here; mock console still linked)  
**Deploy:** `lab/tg544-openwrt/deploy-zone-dashboard.ps1 [-HostAddr 192.168.1.130]`. Uploads web files + CGI only; does **not** overwrite `/etc/ccli/lab.yaml` or the binary.  
**Preview off-device:** serve `lab/tg544-openwrt/www/ccli/` and open `zone_dashboard.html?demo=1` (synthetic data, badge shows DEMO).

Read-only. It never sends Operate / 104 commands (DSO set-points are MMS-only on Eth_A; operator HMI is cloud, REQ-OP-CLOUD-001).

| Tab | Source |
|-----|--------|
| Overview | Single-line (DG / DDI / DDG / PdC / GenPV) + zone summary; breakers show "no feed" (IDGXCBR1 STUB) |
| DSO · LAN1 | `zones.dso`: MMS server, sessions, GNSS, last accepted Wlim / WSd / VArSd / PFSP |
| Operator · LAN2 | `zones.operator`: 104 slave, Operating Rule allow-list, IOA table (`sent_on_wire` false for TotVAr / PPV) |
| Plant · LAN3 / RS485 | `zones.plant` + `plant_map.json`: polled meter, POC map, inverter cards, fan-out controls |
| Events | `?action=events` |

`plant_map.json` (schema `ccli-plant-ui-map/1`) is generated by `python scripts/plant-map-generate.py` from `PLANT_ASSIGNMENT_PLANE.csv`. Inverter cards say **mapped, not polled** because ccli currently polls one meter slave only.

The status JSON `zones` block needs **ccli r33+**. Older binaries keep every existing key (the mock console is unaffected) and the dashboard shows a "deploy ccli r33+" notice.

## Requirements

- **`ccli`** with `--bench-status` / `--bench-write-config` (rebuild `ccli-bin`)
- **`/etc/init.d/ccli`** running (Modbus RTU + DIO)
- **uhttpd** with CGI (`cprefix=/cgi-bin`)
- PC **Modbus slave** on A2/B2 for live **P** (see `MODBUS_LIVE_VIEW.md`)
