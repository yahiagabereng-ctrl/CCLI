# CCI IEC mandatory implementation map

Date: 26 October 2026 (Europe/Rome).

**Updated implementation-status review:** [28 October 2026 reassessment](COMPLIANCE_STATUS_2026-10-28.md) and [assessed requirement/task register](register-assessed-2026-10-28.json). Use that review for current code, deployed r71 evidence, gaps and deferred OCSP. The tables below retain the original standards inventory; older baseline/source-status statements are historical and superseded by the reassessment.

**Scope:** all 47 named IEC 62443-4-1 requirements; all 43 substantive shared IEC 62443-4-2 CRs, four common constraints, all 30 type-specific requirements and every requirement enhancement; EN IEC 62351-3:2023 generic, TLS1.2, TLS1.3, prohibition, event and conformance requirements. Optional/recommended features are retained and labeled separately.

The register contains **531 engineering tasks across 289 requirement/profile families**. These are implementation breakdown counts, not numbers assigned by IEC. All delivery states start Open. Existing implementation evidence is a starting point, not an acceptance result.

## How to implement

1. Freeze the product boundary, chosen FR security-level vector, TLS versions, client/server roles and one repository/build/configuration baseline. All security-level enhancements remain inventoried; none is silently excluded. A feature not used can only be marked N/A with a recorded applicability decision.
2. Assign each task to a named person. Implement the capability or demonstrate an existing implementation at the mapped location. Retain positive/negative tests, or approved process records for organizational requirements.
3. Apply required tester independence. Security-requirements and threat-mitigation testing need an independent department. Abuse-case, attack-surface and known-vulnerability testing need an independent person. Penetration testing needs an independent department or organization. Static/composition analysis needs no independence.
4. Attach evidence and reviewer before marking Closed. Resolve the separately listed scope/source decisions and referenced normative dependencies before final conformance signoff.

This is an engineering paraphrase of the supplied standards. Applicability is part of the requirement: a mandatory enhancement at SL3 is not automatically an SL2 obligation, and selecting optional TLS1.3 activates its mandatory profile. Implementing all rows blindly would also conflict with the rows that prohibit features.
