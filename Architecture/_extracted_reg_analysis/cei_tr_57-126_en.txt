1 Introduction  
This TR offers guidance on the engineering of the Central Plant Controller and its application 
to a Use Case (an example of a plant with a well -defined internal structure and meeting the 
requirements of IEC 0 -16), arriving at the realization of the SCL fil e of the CPC configuration.  
The functional performances covered by this TR are those that are mandatory (Observability) 
and optional ones (Controllability).  
2 Scope  
CEI 0-16 has chosen, among various available technologies, the use of the IEC 61850 standard 
for the  communication between CPC and DSO1. Since this standard is very broad in its structure 
and in its applicability to various areas of the (electrical) power world, we aim to provide a 
practical example of implementation of the Data Model and Communication in compliance with 
Annex O of CEI 0 -16:2022 -03 and Annex T of CEI 0 -16;V3 . 
This TR is intended to facilitate the implementation uniformity of the IEC 61850 interface at the 
CPC terminals for the purpose of high interoperability between IEDs CPC with the role of IEC 
61850 Server on the DER plant side, IEC 61850 Client on the DSO s ide of different 
manufacturers, present in DER plants and  DSO 1) substations, minimization of potential 
errors/implementation gaps due to possible interpretations of the national standard.  
It is also believed that this TR can be useful in a technical discussion among the parties involved 
in the implementation of Smart Grid systems connected to the MV grid.  
  
 
 
1) Annex T refers to the possible use of the IEC 61850 standard also for communication between CPCs and other

3 Terms and definitions  
3.1 
Configured IED Description (CID)  
SCL file of engineering an IED with the instantiation of both the data models and the 
communication for the commissioning of the device  
3.2 
Central Plant Controller (CPC)  
Apparatus whose main functions are plant monitoring, data exchange between the plant and 
the DSO and any additional enabled remote actors, as well as the regulation and control of the 
plant itself  
3.3 
Data Object (DO)  
Part of an LN object that represents specific information, e.g., status or measurements  
3.4 
Distribution System Operator (DSO)  
Electric power distribution utility  
3.5 
Adjustment Function (AF)  
CPC function related to PF2  
3.6 
Intelligent Electronic Device (IED)  
Any device that incorporates one or more processors with the ability to receive/send 
data/control from/to an external source (e.g., multifunction electronic meters, relays digital, 
controllers)  
3.7 
Interoperability  
Ability of two or more FDI from the same or different suppliers to exchange information and use 
that information for the proper execution of specific functions  
3.8 
Logical Node (LN)  
The smallest part of a function that exchanges data. An LN is an object defined by its data and 
methods  
3.9 
Logical Device (LD)  
Virtual device that exists to allow aggregation of related logical nodes  
3.10  
Physical Device (PD)  
equivalent to an FDI as used in the context of the IEC 61850 standard  
3.11  
Functional Performance (FP)  
Set of functions aggregated according to the classification proposed in Annex O: Mandatory  
(FP1 - Observability), Optional (FP2 - Controllability), Optional (FP3 - MSD)  
3.12  
Single Generation Group (SGG)  
Generator whose Nominal Power exceeds the observability threshold provided in O.8.4  
3.13  
Substation/System Configuration Language (SCL)  
System (formerly Substation) Configuration description Language is the format specified by IEC 
61850 for the configuration of electrical station/plant devices and systems.

5 The engineering of the CPC according to Annex T to CEI 0 -16 
5.1 General Information  
The description of the example plant to which to apply what is discussed in the sections of this  
Chapter can be found in Chapter 6 (with reference also to Figure 1 and Figure 2).  
The CPC, as a server, implements the IEC 61850 Ed.2.0 standard and related SCL and scheme  
(reference to T.3.2.1).  
The name of the CPC, to be used within the CID file, will be assigned according to a convention  
agreed between the DSO and the organization to which the plant belongs and respecting the 
constraints  provided by the IEC 61850 scheme (length, characters allowed), shall be unique for 
the client of the DSO to which it connects and thus allow unambiguous information exchange 
at all levels of the Data Model.  
5.2 The CPC Data Model  
The CPC Data Model, for all functional benefits/performances (mandatory and optional) is 
implemented by instantiating the data classes provided in T.3.3.1 (and sub -clauses) and, as 
prescribed, will be organized within a single Logical Device LD_Plant.  
Having Annex T already defined the prefixes and distinguished the types of LNs in order to 
highlight the different DO compositions within LNs of the same class, in the next paragraphs it 
is considered useful to evidence only those sections of the CID file that require specialization 
by the configurator 2) based on the structural/construction characteristics of the individual plant.  
The parts that are, on the other hand, common for any installation, thus already well defined in 
Annex T, will be directly implemented in the CID file without further description.  
5.2.1  Functional Performance PF1 (Observability)  
The Data Model concerning the Observability is based on the classes prescribed in T.3.3.1.1 
and relevant  sub-clauses.  
5.2.1.1  FDI License Plate Information  
With reference to T.3.3.1.1.2, the configurator shall:  
‒ LPHD/PhyNam/Vendor -> enter the name of the Manufacturer of the CPC,  
‒ LPHD/PhyNam/swRev -> enter the SW Version of the CPC,  
‒ LPHD/PhyNam/location -> enter the Identifier of the CP (POD).

powers)

of the plant,  
‒ CP_WaDPCC/WRtg/setMag/f -> enter the value of the maximum active Power in absorption 
(kW) of the plant,

5.2.2  PF2 Functional Performance (Controllability)  
The Data Model relevant to Controllability is based on the classes prescribed in T.3.3.1.2 and  
Sub-clauses.  
The Controllability Functions are optional, however the CPC will have the Data Model capability  
able of instantiating all of them. According to the Operating Rules (Annex U), the DSO will be  
aware of only those FRs that can be enabled and parameterized during the plant control 
process.  
For each i -th Regulatory Function (FRi) among the regulated ones:  
1) active power limitation (reference T.3.3.1.2.1),  
2) modulation of active power input/absorption to the CP ( reference T.3.3.1.2.2),  
3) voltage regulation with delivery of  reactive Inductive/Capacitive power (reference 
T.3.3.1.2.3),  
4) power factor set point (reference T.3.3.1.2.4),  
5) Q(V) (reference T.3.3.1.2.5),  
6) cosϕ = f(P) (reference T.3.3.1.2.6),

5.3 The communication of the CPC according to Annex T to CEI 0 -16 
Annex T is eminently focused  and in detail on data modeling yet  keeping conceptual levels 
with regard to  
‒ protocol services (reference T.3.3.2),  
‒ performance classes and data exchange modes (reference T.3.2.1)  
• Requests (reading/writing) by the client directly,  
• Spontaneous reporting on variations,  
• Periodic reporting,  
suitable for information exchange between the CPC and the DSO 3) without going into the details 
(for generality) about how the data are organized inside the messages on the communication 
interface.  
In this document, however, also this aspect is specified and implemented by taking cue from 
the specifications expressed in T.3.3.1.4, Table 98.  
5.3.1  Communication section  
The IP addressing of the CPC, to be used within the CID file, will be statically assigned 
according to an addressing plan assigned by the DSO; it will have to be unique to enable an 
unambiguous information exchange at all levels of the data model.  
Alternatively, the DSO may offer a DHCP service for dynamic assignment of the address of the 
CPC.  
The sub -network bitrate will reflect the characteristics of the dedicated communication port 
(reference O.13.1.1.1) and the communication infrastructure to which the device is connected.  
5.3.2  Information flows from/to the DSO  
This information exchange takes the form of a Client/Server interaction based on 
communication services whose protocol stack rests on MMS over TCP/IP (with reference to 
T.3.3.3).  
5.3.2.1  Reporting to the DSO (Client)  
With reference to T.3.3.2, the Server (CPC) implements reporting towards the Client (of the 
DSO)  involving both Buffered and Unbuffered messages. The following conventions are 
adopted:  
‒ Data Set for a Report - has the prefix "DS_R_" followed by the descriptive name of the Data 
Set;

With reference to T.3.3.2, the Client (of the DSO) implements a communication to the Server  
(CPC) allowing direct access to specific parts of the model (LD, LN, DO, DA) as well as  to 
structures such as the Control Block, DataSet, etc. as prescribed by the standard for the  specific 
information element and according to access privileges defined by Annex T.
